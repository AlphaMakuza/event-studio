# V2 advanced analysis development build

Open **Analysis → Advanced Analysis** (`Ctrl+Shift+A`) after loading a recording.
The existing project browser, ROI sidebar, slices, raw exports, startup assets,
and scientific/Studio views remain available.

## What is implemented

| Capability | How to use it / current scope |
| --- | --- |
| Activity analytics | Select exact bounds, bin width, polarity and whole field/active ROI/all ROIs. Run analysis for rates, positive/negative activity, cumulative counts and comparisons. Drag an interval in the activity graph to navigate the main viewer. |
| Burst detection | Set a rate threshold and minimum duration. Contiguous bins strictly above the threshold form bursts; empty bins are not detected at threshold zero. Select a result to navigate; convert it to a saved slice. Orange timeline markers identify detected intervals. |
| ROI dashboard | Synchronized named-probe curves use identical half-open bins. Optional per-pixel graph normalization is explicit; measurement CSV rates stay absolute events/ms. |
| Annotations | Save named timestamp markers or current-view intervals, notes, labels, and an optional ROI snapshot. Jump, edit text, delete, export and persist them. Blue markers appear on the timeline. |
| Frequency analysis | The first selected probe receives DC-removed, Hann-window FFT analysis of its event-rate series. Plots show peaks, Nyquist limit and frequency-bin spacing. Export the spectrum and graph. |
| Edge-shift/motion estimation | Enable motion to estimate integer translations between consecutive accumulation images of the first selected probe. View horizontal/vertical estimates, cumulative trajectory, failed links and a quality trace. |
| Micro-motion presentation | Explicitly amplify the estimated motion plot. Amplified plots are STYLIZED, while exported displacement remains unamplified. Optional user-supplied units/pixel calibration changes calibrated output units; pixel estimates remain available. |
| Non-destructive filters | Refractory time, causal prior-neighbor support, whole-recording hot-pixel rate, existing polarity and time/ROI queries. Compare against the unfiltered loaded recording. New slices preserve their filter settings. |
| Batch analysis | Select CSVs and an output directory. Apply shared filtering/bin/threshold settings and optionally named ROIs. Each source/probe receives measurements; a summary reports successes, errors and cancellation. |
| Visualization export | Export aspect-preserving nearest-neighbor PNG sequences with exact frame-time manifests, optional timestamps and visible ROI overlays. FPS, output dimensions and temporal mapping are explicit. |
| MP4 backend | Optional FFmpeg/libx264 encoding of those PNG frames, with recorded encoder version and even-dimension padding. FFmpeg is not installed in the development environment, so actual MP4 encoding has not been verified here. |
| Python interface | `event_studio.api.Recording` exposes loading, querying, statistics, filtering, activity, motion and event export. Numerical modules are reusable without creating GUI windows. |
| Live acquisition adapter | **Analysis → Live camera** uses the optional native Metavision Python SDK, a bounded display buffer, live RAW polarity rendering, ROI statistics and CSV capture. Hardware is not available here: buffer, adapter and capture behavior were tested with a simulated SDK iterator only. |

## Scientific methods and limitations

**Activity.** Integer microsecond arithmetic determines `[start, end)` bins.
Boundary events belong to the next bin. Partial final bins use their actual
duration when computing events/ms. Counts are conserved and source coordinates,
polarity and timestamps are not rewritten. Cumulative plots show accumulated
counts at bin boundaries. Graph x coordinates are relative to the selected
interval to avoid floating-point loss of large absolute timestamps.

**Bursts.** A bin is active only when `events/ms > threshold`. Adjacent active
bins form one interval, without gap interpolation or implicit merging. Export
metadata includes threshold, bin width, minimum duration, source, ROI and filter
settings. Detection accuracy is limited by the chosen bin width; a bin boundary
is not a sub-bin estimate of a physical onset.

**FFT.** Only complete uniform bins enter the FFT; discarding a partial final
bin is explicit in metadata. The mean is removed and a Hann window is applied.
Amplitude is corrected by the window sum, with DC/Nyquist endpoint handling.
The sample rate is `1,000,000 / bin_us` Hz. At least eight full bins are required.
Frequency-bin spacing is not a guarantee that neighboring physical frequencies
are resolvable. Aliasing, event generation, lighting, and windowing all matter.
Event-rate periodicity is **not automatically physical vibration**.

**Motion.** Integer phase correlation compares count images in successive
windows. A maximum displacement search radius, minimum event count and minimum
peak-prominence threshold are visible. The search radius must be less than half
the ROI's shortest side. The method assumes approximately translational image
structure and circular correlation; clipping, repeated texture, occlusion,
changing illumination and sparse activity can produce bad estimates. Peak
prominence is `peak / sum(abs(correlation))`: it is a heuristic, **not a calibrated
probability or physical uncertainty bound**. No subpixel accuracy is claimed.
The first window is a reference, not a displacement measurement. Failed links
are exported as `nan` with reasons, and no silent interpolation bridges them.
Cumulative displacement stays unknown after a broken link. A spatial calibration
is supplied by the user; the application does not infer real-world dimensions
from event counts or certify that calibration. Visual amplification never
changes CSV measurements or source data.

**Main-view motion arrows.** The `MOTION ARROWS` overlay now uses a separate
local normalized-correlation matcher (`local-ncc-v1`), replacing the old grid
centroid subtraction that could turn activity changes into false movement.
Each patch compares the selected window's earlier and later half, with positive
and negative log-count channels kept separate. Spacing controls sampling; patch
support is twice the spacing and search radius is half the spacing. The default
minimum correlation is 0.65. Competing peak basins must differ by at least 0.04;
the local peak exclusion radius is between two and five pixels. Flat or
one-dimensional patches, stationary matches, search-limit peaks, and reverse
matches disagreeing by more than one pixel are suppressed. Correlation is a
similarity score, not a calibrated probability. Neighboring duplicate glyphs
are omitted without averaging or inventing vectors.

Arrows are anchored on matched activity in the later half. **Display ×** changes
glyph length only and now defaults to 1×. **Match quality** controls the minimum
correlation and persists with sessions/render exports. Raise it to reject more
matches. No arrow means stationary or unresolved motion; it does not mean the
region contains no events. If displacement exceeds the search range, narrow the
time window or increase spacing. This method costs more than the old centroid
heuristic (about 240–295 ms per field on sampled 640×480 CARS windows here) and
does not promise real-time optical flow. Existing arrow-mode sessions use the
new estimator; saved explicit display scales remain respected.

**Filtering.** Zero disables a filter. Hot pixels are those whose event count
divided by full-recording duration exceeds the specified events/ms threshold.
Refractory time is measured from the last **retained** event at the same pixel.
Neighbor support checks previous **raw** events at the eight adjacent pixels
within the specified time; it does not use future events or the current pixel
as its own support. The first unsupported events may be rejected. Processing
parameters and retained counts are explicit; loaded raw arrays stay read-only.
Filtered event CSVs retain their processing provenance through their JSON
sidecars; importing one does not restore events that were removed.

**Batch compatibility.** Reusing ROIs requires matching verified sensor
dimensions. A recording with only inferred dimensions is rejected for ROI reuse,
rather than silently assuming its coordinate system is compatible. Supply a
sensor-resolution sidecar or run full-field analysis. Errors are per recording;
they do not prevent valid recordings from finishing. CSV is the batch input
format; use the existing import workflow to convert DAT/H5 first.

**Visual export.** Frame `i` starts at
`start_us + floor(i × 1,000,000 / fps)`. Each accumulation end is clipped to the
selected end. The manifest records every completed frame's actual bounds,
parameters, source and status. PNG sequences are presentation artifacts, not
event recordings. Partial/cancelled sequences retain an honest manifest. MP4
encoding is optional and needs a separately installed FFmpeg executable; its
licensing/build and encoder availability must be appropriate for your use.

## Reproducibility and sessions

Session format **8** adds filter settings, per-slice filter snapshots, analysis
configuration, annotations and detected intervals. Formats 1–7 remain readable.
Numerical results are recomputed from the identified recording and settings,
rather than pretending that cached plots are independent measurements. Save the
project/session after adding annotations or burst slices.

Measurement exports include source identity, exact bounds, ROI coordinates,
polarity/filter parameters, software version, algorithm name/version, units and
CSV SHA-256. Exported graphs have JSON sidecars. Failed event/measurement pair
replacement rolls back an existing pair on ordinary write/replacement errors;
this is not a cross-file power-loss transaction. Session view settings validate
before replacement, and failed restoration preserves the previous analysis.

## Python example

```python
from event_studio.api import Recording, Roi, detect_bursts, frequency_spectrum
from event_studio.io_utils import export_table

recording = Recording.open("recording.csv")
start = int(recording.events.t[0])
end = int(recording.events.t[-1]) + 1
probe = Roi(20, 20, 100, 80)
series = recording.activity(start, end, bin_us=1000, roi=probe)
bursts = detect_bursts(series, threshold=50, min_duration_us=2000)
spectrum = frequency_spectrum(series)  # requires >= 8 complete bins

derived = recording.filtered(refractory_us=100)
stats = derived.statistics(start, end, roi=probe)
derived.export("selected.csv", t0=start, t1=end, roi=probe)
```

`Recording.resolution` is `(height, width)`; its provenance is in metadata.
`query` returns event subsets; it does not make a subset a complete acquisition.
Use `Recording.export` on the recording with explicit selection arguments.

## Live camera prerequisites and boundaries

The adapter follows the documented
[Metavision EventsIterator interface](https://docs.prophesee.ai/stable/api/python/core/event_io.html):
camera serial or empty string for a camera, fixed time batches, reported sensor
dimensions and original timestamps. The SDK must be installed in the **same
Python environment as the GUI**. Existing WSL conversion executables do not
provide Windows Python bindings or a connected camera. The Connect button is
disabled when the native SDK is unavailable.

OpenEB provides open modules and camera plugins; review the actual SDK/device
and redistribution terms for the selected installation. This project does not
bundle or install that SDK. Consult the [official repository](https://github.com/prophesee-ai/openeb)
and its [license](https://github.com/prophesee-ai/openeb/blob/main/licensing/LICENSE_OPEN)
before deploying an acquisition installation; optional proprietary components
are not assumed to be licensed by an open-module license.

Acquisition and CSV writing occur in a worker. Rendering polls a bounded recent
event buffer. Application display-buffer evictions are counted separately;
upstream SDK/hardware drops remain **unknown**, not zero. Capture metadata records
this distinction. A camera error or timestamp reset stops capture rather than
rewriting timestamps. Stop is cooperative at the next SDK delivery; a blocked
device/driver read may delay it. Physical connect/disconnect behavior, throughput,
recording loss and device-specific drop facilities require hardware validation.

## Validation and resource bounds

Run `.\.venv\Scripts\python.exe -B -m unittest discover -s tests -v`.
Tests include known-frequency activity, known image translations, exact large
timestamps and partial bins, causal filters, transactional export failures,
session rollback, overlay restore, final trail updates, burst-to-slice and
annotation workflows, filtered session restoration, batch failures, PNG temporal
mapping, cancellation manifests, sidecar identity, and simulated acquisition.
The native Windows muted short-sound early-stop check now completes successfully.
No assertion of audible output or hardware camera validation is made.

A real CARS recording with 4,829,705 events was analyzed with two 96×96 probes,
150 bins, burst detection, FFT and 150 motion windows in about 0.55 seconds
(excluding loading and display). Three bursts were detected at the selected
10 events/ms threshold. The tracker accepted only **one of 149 links** at the
default peak-prominence threshold on that recording. Synthetic integer shifts
pass numerical tests, but this real example does not establish robust physical
motion measurement. Treat motion/micro-motion tools as **experimental estimates**,
inspect quality/failures, and validate the method for your own scene.

Recordings remain RAM-resident. The API permits at most one million activity
bins; the workspace caps at 100,000 bins, 64 compared probes and 10,000 detected
bursts to avoid unbounded UI tables. Motion caps at 2,000 windows; visual export
caps at 50,000 frames and 16-megapixel output. Increase bin width or narrow the
selection when needed. Offline V2 jobs support cooperative cancellation and
progress. CSV import and existing OpenEB conversion are not forcibly terminated.
There is no GPU/subpixel tracker, out-of-core loader, automatic calibration,
or claim of universally real-time performance on arbitrary recordings.
